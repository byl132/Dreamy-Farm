## 0. 一句话定位

> **《梦幻农场》是一款以"真实农场风"为基调的轻治愈、慢节奏农场经营游戏：玩家在可信的生长节律中耕种、收获、装扮自己的农场，并与邻居温柔连接——没有失败惩罚，只有"我的农场在呼吸"的安心感。**

副标题沿用原型措辞：**"让灵感鲜活落地"**，即游戏的核心情感承诺是"把玩家对田园生活的想象，温柔地变成可触的成长"。

本概念文档是后续所有设计决策的"地基"与"取舍标尺"。所有 Phase 2 起的系统 GDD 都必须向上回溯到本文档的 **游戏支柱（第 1 章）** 与 **动词（第 3 章）**，不得与之冲突。

## 1. 游戏支柱（Pillars）

四条支柱是项目 Phase 1 概念阶段的最高决策标准（**其作为设计标尺的地位已被 `design/gdd/dream-farm-gdd.md` 5 支柱 SSOT 取代，见文档顶部 G8 标注**）。当任一设计取舍出现分歧时，以"是否 strengthening 对应支柱"为裁决依据。四条支柱彼此独立、不重叠。以下保留为概念演进记录。

| # | 支柱 | 一句话 | 阐释（作为取舍标准） |
|---|------|--------|----------------------|
| P1 | **治愈低压力** | 不靠时间惩罚与失败焦虑驱动，任何节奏都能获得正反馈。 | 作物不会"枯萎消失"，没有破产/饥饿失败态；离线也有收益。当有人提议"加个惩罚机制提升留存"时，本支柱说 **不**。 |
| P2 | **真实生长** | 作物、动物、农场遵循一套可信、可读的生长节律（时间 / 季节 / 天气）。 | 每个地块都有从播种到收获的可读状态，时间与天气真实影响节奏，营造"我的农场在呼吸"的实感。当有人想把生长简化为"点一下就好"时，本支柱说 **保留可读生命周期**。 |
| P3 | **自我表达** | 农场是玩家的画布，通过布局、装饰、主题表达个性。 | 呼应副标题"让灵感鲜活落地"。布局自由度与装饰系统让每个农场独一无二。当范围吃紧时，本支柱 **保护装饰与布局系统** 的预算。 |
| P4 | **轻社交连接** | 邻居 / 互访 / 赠礼提供关联感，但非强制、非对抗。 | 社交是"串门"而非"排行榜战争"。鼓励但绝不惩罚。当有人提议 PvP / 排行榜羞辱机制时，本支柱说 **不**。 |

> **支柱自检（自洽性）**：P1 与 P4 共同排除了"惩罚性 / 对抗性"设计；P2 与 P3 共同要求"系统有足够的可读状态与表达空间"；四条合起来定义了本作的边界——**一个真实、温柔、可表达、可轻连接的农场**，而非硬核模拟或竞技游戏。

## 2. MDA 框架分析

MDA（Mechanics–Dynamics–Aesthetics）是本文档的核心分析骨架。Mechanics 是系统实现的规则；Dynamics 是玩家与规则互动后涌现的行为；Aesthetics 是玩家最终获得的"趣味类型"。

### 2.1 Mechanics（核心机制）

下列机制均在现有原型中有明确暗示（括号内为原型证据），属于 Phase 2 需逐系统拆解为 GDD 的对象：

- **格子耕种循环**：4×4 共 16 块地（`farm-grid`）。地块状态机为 `空地 → 播种 → 发芽 → 成长 → 可收获`（`plot-empty / stage-seed / stage-sprout / stage-grow / stage-ready`）。真实计时生长（原型作物生长时间：胡萝卜 3h、向日葵 4h、番茄 5h、小麦 6h、玉米 8h、玫瑰 8h、草莓 10h、南瓜 12h）。
- **资源经济（三通货）**：
  - 金币 🪙（软通货，原型显示 12,580）——耕种与任务产出，商店主流通货。
  - 钻石 💎（硬通货 / 溢价通货，原型显示 256）——玫瑰种子等溢价物品以钻石计价（🎯 15），面向内购。
  - 能量 ⚡（行动点，原型显示 86/100）——每次耕种 / 收获消耗，随时间与离线恢复，是节奏调节器而非惩罚墙。
- **时间系统**：农场时钟（原型 `farm-time` 实时走表）、季节（原型 `第 42 天 · 春季`）、天气（原型 `☀️ 晴朗 · 适宜种植`）。天气影响种植适宜度，是 P2 真实生长的表现层。
- **任务系统**：每日 / 每周 / 特殊 / 成就 四类（`quest-card daily/weekly/special` + `成就` tab），带进度条与奖励（金币 / 经验 ✨ / 钻石 / 神秘礼盒）。活跃度计量（原型 `活跃度 680/1000`）。
- **等级与头衔**：玩家等级（原型 `Lv.12 庄园主`），等级驱动解锁与胜任感。
- **背包与容量**：格状背包（原型 `容量 45/80`），分作物 / 种子 / 工具 / 特殊类目。
- **商店交易**：分类商店（种子 / 工具 / 动物 / 装饰 / 特殊），买卖作物与种子。
- **（未来）动物 / 装饰 / 邻居**：商店已预留"动物""装饰"分类；任务含"动物饲养员""拜访邻居"；Dock 含"邻居"入口（原型标"好友系统即将开放"）。这三者在概念层确认存在，但归属范围分层（见第 5 章）。

### 2.2 Dynamics（玩家行为涌现）

机制经玩家之手后，预期涌现以下行为（用于 Phase 2 验证设计是否生效）：

- **每日巡回仪式**：登录 → 收成熟作物 → 卖钱 → 买种补种 → 清任务。形成稳定日活习惯。
- **晨间收割仪式**：因离线有收益、作物按真实时间成熟，玩家倾向"睡前留作物、晨起收割"，把游戏嵌入生活节律（强化 P1）。
- **能量预算博弈**：玩家在"今天还能种 / 收几块地"间权衡，自发形成上线节奏——这是低压力下的"温柔挑战"，而非硬墙。
- **装饰驱动分享**：自由布局与装饰让玩家截图、向邻居炫耀，带来有机传播（强化 P3）。
- **收集驱动**：图鉴 / 成就 / "收藏大师"类任务（原型每周任务）让玩家追求全收集，提供长线目标。
- **串门经济（未来）**：互访、赠花、互助任务形成温和的礼物经济，强化 P4 关联感。

### 2.3 Aesthetics（目标趣味类型）

对照 LeBlanc 八类趣味，本作的目标定位如下：

| 趣味类型 | 是否目标 | 说明 |
|----------|----------|------|
| **Submission（放松 / 沉浸 / 消遣）** | ⭐ 主目标 | 治愈基调的核心交付物，对应 P1。 |
| **Expression（表达）** | ⭐ 主目标 | 装饰 / 布局 / 主题自由，对应 P3，是差异化核心。 |
| **Discovery（发现）** | ◐ 次目标 | 新作物、季节事件、图鉴、隐藏装饰，支撑 P2 真实感与长线探索。 |
| **Fellowship（社交）** | ◐ 次目标 | 邻居 / 赠礼 / 互访，对应 P4。 |
| Sensation（感官刺激） | 辅助 | 靠"视觉锚点"（第 6 章）的美术与动效间接提供，非设计重心。 |
| Fantasy（幻想扮演） | 弱 | 本作是"真实农场风"而非奇幻，幻想成分刻意压低。 |
| Narrative（叙事） | 弱 | 仅以轻量世界观 / 季节活动承载，不做主线剧情。 |
| Challenge（硬挑战） | **排除** | 与 P1 治愈低压力直接冲突，不做硬核挑战 / 失败。 |

> **美学自检（自洽性）**：主目标 Submission + Expression 与 P1 / P3 一一对应；次目标 Discovery + Fellowship 与 P2 / P4 对应；被排除的 Challenge 与 P1 一致。八类趣味无内部矛盾。

## 3. 动词优先法（Verb-first）

玩家在《梦幻农场》里反复做的核心动词，是系统存在的理由。每个动词都必须能回溯到至少一个支柱。定义 **2 个核心循环动词**（构成最小可玩闭环）与 **2 个表达 / 连接动词**（构成差异化与长线）。

| 动词 | 玩家做什么 | 支撑的支柱 | 设计含义 |
|------|------------|------------|----------|
| **① 种植 Plant** | 选作物 → 在格子上播种 → 等待真实生长 | P2（真实生长）、P1（等待是温柔的） | 动词背后必须是"播种 → 成熟"的可信节律，不能省略中间态。 |
| **② 收获 Harvest** | 点击成熟作物 → 入背包 → 即时正反馈 | P1（治愈正反馈）、P2（生长闭环） | 收获动作要"爽"且零挫败，是每日仪式的情绪高点。 |
| **③ 装扮 Decorate** | 摆装饰、调布局、换主题 | P3（自我表达） | 差异化核心动词；布局自由度与装饰种类是预算保护对象。 |
| **④ 串门 Visit** | 拜访邻居、赠礼、互助 | P4（轻社交连接） | 非强制、非对抗；动词设计以"温暖小事"为单位（送一朵花、帮浇一次水）。 |

> **动词 → 系统映射（Phase 2 预告）**：①+② → 耕种系统 / 时间系统；③ → 装饰与布局系统；④ → 邻居 / 社交系统。经济系统（金币 / 钻石 / 能量）横穿所有动词，是"动词的燃料"。

## 4. 玩家心理学

### 4.1 自我决定论（SDT，三需求）

| 需求 | 本作如何满足 | 对应设计 |
|------|--------------|----------|
| **自主 Autonomy** | 玩家自由决定种什么、何时上线、如何布局、是否社交；任务为可选而非强制日程。 | 无强制登录惩罚；布局自由；邻居可忽略而不受罚（P1 / P4）。 |
| **胜任 Competence** | 等级 / 头衔 / 任务进度 / 图鉴完成度提供可见成长与掌控感；能量与资源让玩家感到"经营有方"。 | 等级头衔、任务进度条、图鉴、活跃度（原型 680/1000）。 |
| **关联 Relatedness** | 邻居 / 赠礼 / 互访 / 季节活动（如春日庆典）提供归属感。 | 邻居系统、赠礼、限时活动（P4）。 |

### 4.2 心流与难度曲线（Flow）

- **基调**：治愈游戏需把"挑战"压到 **低但非零**。本作的"挑战"不是操作难度，而是 **温和的优化问题**——能量预算、为活动卡作物时机、布局审美。
- **技能成长**：随等级解锁新作物 / 工具 / 地块，玩家"经营技巧"随内容解锁而上升，曲线平滑。
- **防无聊下限**：纯低压力会滑向无聊（心流过低）。用 **分层目标** 维持下限：每日轻目标（收割 5 次）→ 每周 / 收集长目标（收藏大师）→ 季节限时活动（春日庆典）。目标层层递进，保证"随时有件小事可做"。
- **会话友好**：设计必须支持"可中断、随时回归"——上线即结算离线生长（见第 7 章数据同步），不让玩家因离开而损失，保护 P1。

### 4.3 Bartle 玩家类型

| 类型 | 服务级别 | 说明 |
|------|----------|------|
| **成就者 Achievers** | ⭐ 主要 | 任务、等级、头衔、图鉴、活跃度、收藏大师——原型任务中心即为此类玩家设计。是营收与留存主力。 |
| **探索者 Explorers** | ◐ 次要 | 发现新作物、季节事件、图鉴空缺、隐藏装饰（Discovery 趣味）。 |
| **社交者 Socializers** | ◐ 次要 | 邻居互访、赠礼、晒农场（Fellowship 趣味，P4）。 |
| **杀手 Killers** | **不服务** | 无 PvP、无对抗、无排行榜羞辱，与 P1 / P4 冲突，明确排除。 |

> **心理学自检（自洽性）**：SDT 三需求分别由 P1/P2/P4 的设计承接；Flow 的"低但非零挑战"与 P1 不矛盾（是温柔优化而非硬挑战）；Bartle 主要服务 Achievers，与"任务 / 等级 / 图鉴"机制一致，Killers 排除与 P1/P4 一致。

## 5. 范围分层（Scope Layering）

明确"每层有什么、砍掉什么"，是后续排期与 Phase 2 拆解的直接输入。

### 核心（Core Loop · 必须有的最小可玩集）
构成"游戏之所以是游戏"的闭环，缺一不可：
- 4×4 耕种网格 + 8 种基础作物（胡萝卜 / 向日葵 / 番茄 / 小麦 / 玉米 / 玫瑰 / 草莓 / 南瓜）的真实计时生长。
- 资源经济三件套：**金币 + 能量**（钻石在核心层仅作占位，不强制）。
- 收获 → 背包 → 商店买卖 的基础闭环。
- 基础任务（每日）+ 玩家等级 / 头衔。
- **砍掉**：季节 / 天气深度、邻居、动物、装饰、图鉴、钻石内购、云端多端同步（核心层可单机本地存档）。

### MVP（首可玩版本 · 第一个可发布雏形）
核心闭环 + 让游戏"成立且能跨端玩"的最小增量：
- **云端存档 + 多端登录**（服务器权威，见第 8 章风险 1）——这是 MVP 的硬门槛，因为多端是已锁定平台。
- 时间与 **季节 / 天气可读**（影响生长适宜度，落地 P2）。
- 任务扩展为 每日 / 每周 / 成就；**图鉴系统**（支撑 Discovery 与 Achievers）。
- **钻石硬通货 + 单一首充 / 内购点**（验证商业化，不铺量）。
- **基础装饰解锁**（少量装饰物，落地 P3 最小表达）。
- **邻居 1.0**：互访 + 赠礼（落地 P4 最小连接），不含复杂社交图。
- **砍掉（留到扩展）**：动物、完整装饰 / 主题包、季节限定大活动、贸易市场、社交 2.0。

### 扩展（后续版本 · v1.x+）
- 动物系统（鸡 / 牛 / 羊，含"动物饲养员"任务落地）。
- 完整装饰 / 主题包（四季主题、布局模板）。
- 邻居社交 2.0：串门经济、互助任务、好友列表。
- 季节限定活动（如原型"春日庆典"正式化，含专属装饰解锁）。
- 高级工具（化肥加速、超级水壶、金铲子——原型背包已暗示）。
- 贸易市场 / 玩家间交易、小镇 / 公会。

### 愿景（长期目标 · v2+）
- UGC 装饰编辑器 / 创意工坊式玩家自制装饰。
- 跨平台"大农场"与全球农场展览（玩家互访的规模化）。
- 轻量叙事线（世界观承载于季节事件，不做主线剧情，呼应 Narrative 弱定位）。
- 公益 / 可持续联动（如真实植树映射），延展"让灵感鲜活落地"的情感外延。

> **范围自检（自洽性）**：核心层不含邻居 / 装饰 / 钻石内购，与第 3 章"①② 为最小闭环"一致；MVP 才引入邻居 1.0 与基础装饰，与 P3/P4"在 MVP 落地最小表达 / 连接"一致；被排除的 Killer 类玩法不出现在任何层。

## 6. 视觉锚点（Visual Anchors · 供 art-director 对齐）

以下锚点用文字锁定"情绪 + 色彩 + 构图"，直接引用原型已建立的调色板（金 `#C9A227` / 森林绿 `#4A7C59` / 赤陶 `#C4854A` / 奶油 `#FDF6E9` / 木 `#8B5E3C` / 棕 `#3E2723` / 天空蓝 `#87CEEB` / 沙 `#F0E4D0`）。art-director 据此起草美术圣经（Art Bible），须与本文档情绪一致。

1. **晨光金麦田** — 清晨斜射光下，金色麦浪（`#C9A227` 系）与森林绿田垄（`#4A7C59`）的对比。情绪：希望、开始、治愈。对应登录页天空→沙→绿渐变构图。
2. **毛玻璃温柔 UI** — 半透明白卡片 + 模糊背景悬浮于农场之上（原型 `backdrop-filter: blur` 的登录卡与顶栏），信息轻、不抢景。情绪：现代、柔和、呼吸感。⚠️ 注意：此锚点在移动端有性能代价，落地方式见第 7 章。
3. **真实可触的泥土与作物** — 地块用斜纹泥土纹理（`#8B5E3C` / `#A08060`，原型 `plot-empty` 条纹），作物用高饱和、带投影的卡通插画 / emoji 风（原型 `plant-stage`）。情绪：可信、可玩、童趣而不幼稚。定调 **"写实色调 + 卡通表现"**。
4. **季节情绪色** — 春（嫩绿 + 花）、夏（浓绿 + 晴蓝 `#87CEEB`）、秋（赤陶 `#C4854A` + 金）、冬（奶油 `#FDF6E9` + 冷调）。情绪：时间流逝的诗意，支撑 P2 真实生长。
5. **夜晚暖灯农场** — 入夜后地块边缘亮起暖金小灯，营造"归家"安全感。情绪：归属、安宁，呼应 P4 与"我的农场在呼吸"。

## 7. 平台与引擎约束下的设计考量（Unity + 多端）

已锁定 **Unity + 多端（Web / iOS / Android）**。以下为设计层必须前置考虑的约束，具体实现由程基岩在 Phase 3 技术搭建确认，本文档仅定义"设计不能踩的坑"。

- **UI 适配（响应式三档）**：原型用 CSS `@media (max-width:768px)` 隐藏侧栏、改网格列数。在 Unity 中需建立 **竖屏移动 / 横屏平板 / 桌面窗口** 三档断点 + 安全区（刘海 / Home Indicator）。底部 Dock（原型 `bottom-dock`）须落在移动端拇指热区；窄屏隐藏侧栏（如原型 `side-panel` 在 ≤768px `display:none`）。
- **输入差异（去 hover 依赖）**：移动端以 **点按 / 长按 / 滑动** 为主，Web 有鼠标 hover。设计 **不得依赖 hover 承载关键信息**（原型大量用 `:hover` 抬升动画，移动端须转为点击态 / 常驻态）。地块信息（如 `showPlotInfo`）在移动端用点击弹层而非悬停。
- **性能预算（毛玻璃代价）**：Web 的 `backdrop-filter: blur` 廉价，但在 Unity / 移动 GPU 上 **实时模糊成本高**。设计层决策：用 **"预模糊背景 sprite + 半透叠加"** 替代实时模糊，或严格限制模糊层数（呼应第 6 章锚点 2 的 ⚠️）。同时约束同屏动画数量（如原型成熟作物 `bounce` 弹跳）、地块实例数、纹理内存，照顾中低端 Android。
- **数据同步（服务器权威 + 离线结算）**：多端同账号 → **云端存档、服务器权威经济**。关键设计点：生长 **绝不用客户端计时**，而用 **"服务器时间戳离线结算"**——上线时按真实流逝时间结算成熟，既支持 P1 的离线收益，又杜绝改本地时钟加速（见第 8 章风险 1）。
- **表现 / 逻辑分离**：UI（UGUI 或 UI Toolkit）与游戏逻辑（C#）须分层，保证 WebGL 与 IL2CPP 移动包共享同一套经济 / 耕种逻辑。具体架构由程基岩在 Phase 3 确认，本文档要求"概念上逻辑与表现可分离"。

## 8. 已知风险与缓解（概念层）

| # | 风险 | 概念级应对方向 |
|---|------|----------------|
| R1 | **多端经济作弊**（客户端改金币 / 加速生长） | 服务器权威经济 + 离线用时间戳结算（非本地计时）+ 关键交易服务端校验。这是 MVP 必须云端存档的根本原因（见第 5 章）。 |
| R2 | **毛玻璃性能掉帧**（移动端实时模糊） | 设计改用预模糊背景 / 限制模糊层（第 6 章锚点 2、第 7 章性能预算）。 |
| R3 | **治愈滑向无聊（Flow 风险）** | 分层目标（每日→每周 / 收集→季节活动）维持心流下限；用渐进解锁制造胜任感（第 4.2 章）。 |
| R4 | **能量门控导致流失** | 能量定位为"节奏调节器"而非"墙"：恢复快、离线恢复、可用金币温和补能但限制硬通货消耗；绝不让能量成为 P1 所说的惩罚（第 2.1、第 4.1 章）。 |
| R5 | **多端同步冲突**（同账号双端同改） | 字段级合并 + 冲突解决策略，或单端活跃会话限制；由程基岩 Phase 3 落地。 |
| R6 | **范围蔓延（装饰 / 社交无限扩）** | 以 P3 / P4 给预算上限，MVP 只放最小装饰与邻居 1.0（第 5 章）。 |
| R7 | **真实感 vs 可爱感失衡** | 定调"写实色调 + 卡通表现"（第 6 章锚点 3），避免过写实破坏 cozy 基调。 |
